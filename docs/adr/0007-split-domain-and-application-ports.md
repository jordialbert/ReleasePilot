# Split Domain and Application ports

Ports are placed by whether they name a business capability in the domain language or a mechanism of the application. Repository interfaces, `IDomainEventBus`, and the external-system ports that express domain capabilities — `IDeploymentPort`, `INotificationPort`, and `IIssueTrackerPort` — live in Domain: deploying a Promotion, notifying on terminal states, consulting Work Items linked to a version, and publishing the Domain Events a transition records are things a release manager would say. `IUnitOfWork` and `ILanguageModelPort` live in Application: a transaction and a language model are how the application happens to fulfill its job, not vocabulary of the release process. Notably, `ReleaseNotesDraft` and `IReleaseNotesRepository` remain Domain while the LLM that authors the draft is mechanism. `IIssueTrackerPort` keeps the challenge's port name for traceability even though the ubiquitous language prefers Work Item over Issue. Infrastructure provides adapters for ports in both layers.
